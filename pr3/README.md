# Практична робота №3 — інтеграція Gemini LLM через API

## Мета

Розробити FastAPI-застосунок — помічник служби підтримки інтернет-магазину, який відповідає українською на основі локального файлу `context.md` через OpenAI-сумісний Gemini API.

## Можливості

- Вебсторінка з формою запитання та форматованою відповіддю Markdown.
- Окремі системна інструкція, контекст магазину та звернення користувача.
- Правила зчитуються з `context.md` під час кожного запиту.
- Конфігурація API у локальному `.env`, який не додається в Git.
- Обробка помилок авторизації, ліміту запитів, таймауту, мережі та 5xx.
- Відображення назви моделі та тривалості відповіді.
- Ручне порівняння двох температур у `compare/findings.md`.

## Запуск у Windows (PowerShell)

Відкрийте термінал у папці `pr3`:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Відкрийте `.env`, заповніть `LLM_API_KEY` **новим приватним ключем**, а також перевірте модель, яка працює у вашому Google AI Studio. Приклад робочих налаштувань:

```env
LLM_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
LLM_API_KEY=ВАШ_КЛЮЧ_ЛИШЕ_ЛОКАЛЬНО
LLM_MODEL=gemini-3.5-flash
LLM_TEMPERATURE=0.2
LLM_MAX_TOKENS=4096
LLM_TIMEOUT=120
```

**Не публікуйте `.env` і не вставляйте ключ у GitHub.** Якщо ключ колись надсилали у чат, відкличте його та створіть новий.

Запуск:

```powershell
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Відкрийте `http://127.0.0.1:8000`. Документація API: `http://127.0.0.1:8000/docs`.

## Як перевірити вручну

1. Відкрийте вебсторінку і введіть: **«Які способи оплати доступні?»**. Перевірте відповідь за `context.md`.
2. Запитайте: **«Скільки триває доставка?»**. Перевірте строки й умови в контексті.
3. Запитайте: **«Чи можу я змінити склад оформленого замовлення?»**. Перевірте відповідність політиці магазину.
4. Запитайте: **«Як скасувати замовлення?»**. Перевірте обмеження за статусом.
5. Запитайте: **«Чи доставляєте ви за кордон?»**. Якщо у `context.md` немає відповіді, помічник має визнати нестачу інформації, а не вигадувати умови.
6. Запитайте: **«Хочу повернути товар»**. Перевірте, чи відповідь спирається на правила та чи модель уточнює відсутні дані, коли це потрібно.
7. Для порівняння залиште `LLM_TEMPERATURE=0.2`, задайте ці шість запитань, запишіть короткі результати й час у `compare/findings.md`.
8. Зупиніть сервер (`Ctrl+C`), змініть у `.env` `LLM_TEMPERATURE=0.8`, запустіть сервер знову та повторіть шість запитань. Заповніть другу колонку й висновок.
9. Для перевірки зміни контексту тимчасово відредагуйте одну несекретну умову в `context.md`, поставте відповідне запитання та переконайтеся, що відповідь змінилася. Поверніть початковий текст перед комітом.
10. Для перевірки помилки API тимчасово використайте неправильний ключ лише локально, зробіть запит і переконайтеся, що відображається повідомлення про авторизацію. Відновіть правильний ключ.

**Примітка:** температура впливає на варіативність, але не гарантує відмінностей у кожній відповіді. Фактичні результати експерименту заповнюються вручну.

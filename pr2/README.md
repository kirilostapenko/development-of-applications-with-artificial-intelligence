# Практична робота №2. Локальний inference спеціалізованої моделі

## 1. Мета роботи

Навчитися інтегрувати готову модель штучного інтелекту у вебзастосунок, виконувати локальне розпізнавання об'єктів на зображеннях, обробляти результати роботи моделі та оцінювати якість розпізнавання.

## 2. Опис проєкту

У межах практичної роботи розроблено вебзастосунок для автоматичного виявлення об'єктів на зображеннях.

Для розпізнавання використовується попередньо навчена модель **YOLOv8n** із бібліотеки Ultralytics.

Застосунок розроблено мовою Python із використанням фреймворку FastAPI. Вебінтерфейс реалізовано за допомогою HTML, CSS та JavaScript.

Обробка зображень виконується локально на комп'ютері користувача без надсилання фотографій до зовнішнього сервісу штучного інтелекту.

### Основні можливості

- Завантаження зображень через вебінтерфейс.
- Автоматичне виявлення об'єктів за допомогою YOLOv8n.
- Визначення класу кожного знайденого об'єкта.
- Відображення впевненості моделі (confidence).
- Отримання координат обмежувальних рамок (bounding boxes).
- Налаштування порога впевненості від 0 до 1.
- Підрахунок кількості знайдених об'єктів.
- Вимірювання часу виконання inference у мілісекундах.
- Обробка помилок у разі завантаження некоректного або порожнього файлу.
- Повернення результатів у форматі JSON.

## 3. Використані технології

| Технологія | Призначення |
|---|---|
| Python | Основна мова програмування |
| FastAPI | Створення вебзастосунку та API |
| Ultralytics YOLOv8n | Розпізнавання об'єктів |
| PyTorch | Виконання нейромережевих обчислень |

## 4. Структура проєкту

```text
pr2/
├── app/
│   ├── __init__.py
│   ├── main.py
│   ├── detector.py
│   └── templates/
│       └── index.html
├── eval/
│   ├── README.md
│   └── expected.example.json
├── check_env.py
├── requirements.txt
└── README.md
```

Призначення основних файлів:

- `app/main.py` — вебсервер FastAPI, маршрути та обробка HTTP-запитів.
- `app/detector.py` — завантаження моделі YOLOv8n, виконання детекції та формування результатів.
- `app/templates/index.html` — вебінтерфейс для завантаження зображень і перегляду результатів.
- `check_env.py` — перевірка Python, необхідних бібліотек та доступності ваг моделі.
- `requirements.txt` — список залежностей.
- `eval/README.md` — результати експериментів, порівняння розпізнавань та аналіз помилок.
- `eval/expected.example.json` — приклад структури файлу з очікуваними об'єктами.

Локально також використовуються папка `eval/images/` із тестовими фотографіями та файл `eval/expected.json` з очікуваними результатами.

## 5. Встановлення та запуск

### Крок 1. Перейти до папки практичної роботи

```bash
cd pr2
```

### Крок 2. Створити віртуальне середовище

```bash
python -m venv .venv
```

### Крок 3. Встановити залежності

Для Windows:

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### Крок 4. Перевірити середовище

```bash
.venv\Scripts\python.exe check_env.py
```

Під час першого запуску може автоматично завантажуватися файл ваг моделі `yolov8n.pt`.

### Крок 5. Запустити вебсервер

```bash
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Після запуску відкрити у браузері:

**http://127.0.0.1:8000**

Інтерактивна документація API доступна за адресою:

**http://127.0.0.1:8000/docs**

## 6. Принцип роботи програми

1. Користувач відкриває вебсторінку застосунку.
2. Завантажує фотографію.
3. Встановлює поріг впевненості (за замовчуванням 0.25).
4. Натискає кнопку «Знайти об'єкти».
5. Сервер отримує зображення та перевіряє його коректність.
6. Модель YOLOv8n виконує локальне розпізнавання.
7. Для кожного об'єкта визначаються клас, confidence та координати рамки.
8. Програма вимірює час виконання inference.
9. Результати повертаються у форматі JSON та відображаються у вебінтерфейсі.

Модель завантажується один раз під час запуску сервера, а не повторно для кожного зображення.

## 7. API застосунку

### GET /

Відкриває головну сторінку вебзастосунку.

### POST /api/detect

Приймає зображення та параметр `confidence`.

Параметри запиту:

- `image` — файл зображення.
- `confidence` — поріг упевненості від 0 до 1.

Успішна відповідь містить:

- `image` — ширину та висоту зображення;
- `confidence_threshold` — використаний поріг;
- `count` — кількість знайдених об'єктів;
- `inference_time_ms` — час розпізнавання;
- `detections` — список знайдених об'єктів.

Кожен елемент `detections` містить ідентифікатор класу, його назву, впевненість моделі та координати рамки `x1`, `y1`, `x2`, `y2`.

## 8. Тестування моделі

Для оцінювання роботи моделі використано п'ять тестових зображень:

1. `person.jpg` — людина.
2. `bottle.jpg` — пляшка.
3. `beach.jpg` — пляжна сцена.
4. `car.jpg` — автомобіль.
5. `chair.jpg` — стілець.

Під час тестування порівнювалися очікувані об'єкти та результати моделі.

### Результати при порозі confidence 0.25

| Зображення | Очікуваний об'єкт | Результат моделі | Час (мс) |
|---|---|---|---|
| person.jpg | person | person | 55.09 |
| bottle.jpg | bottle | vase | 60.97 |
| beach.jpg | Немає цільового об'єкта | kite | 89.40 |
| car.jpg | car | train | 52.77 |
| chair.jpg | chair | chair та інші класи | 133.44 |

Модель правильно визначила людину та стілець, але для деяких зображень виникли помилки класифікації.

У випадку `bottle.jpg` пляшку було класифіковано як вазу. Для `car.jpg` замість автомобіля визначено поїзд.

На зображенні `beach.jpg` модель виявила об'єкт класу `kite`. Класу `beach` немає серед класів COCO, оскільки модель призначена для виявлення окремих об'єктів, а не класифікації типу місцевості. Правильність виявлення `kite` залежить від фактичного вмісту фотографії.

### Порівняння різних порогів confidence

| Зображення | 0.25 | 0.50 | 0.75 |
|---|---:|---:|---:|
| person.jpg | 1 | 1 | 1 |
| bottle.jpg | 1 | 1 | 0 |
| beach.jpg | 1 | 0 | 0 |
| car.jpg | 1 | 0 | 0 |
| chair.jpg | 9 | 5 | 1 |

Зі збільшенням порога впевненості кількість виявлених об'єктів зменшується.

Нижчий поріг дозволяє отримати більше розпізнавань, але може збільшувати кількість хибних спрацювань. Вищий поріг відкидає менш упевнені результати, проте може призводити до пропуску реальних об'єктів.

Детальні результати та аналіз помилок наведено у файлі `eval/README.md`.

## 9. Обробка помилок

У програмі передбачено обробку таких ситуацій:

- Порожній файл — HTTP 400.
- Некоректне зображення — HTTP 400.
- Неправильний поріг confidence — HTTP 422.
- Помилка виконання детекції — HTTP 503.
- Неочікувана внутрішня помилка — HTTP 500.

У разі помилки користувач отримує відповідне повідомлення.

## 10. Висновок

У ході практичної роботи розроблено вебзастосунок для локального розпізнавання об'єктів на зображеннях за допомогою попередньо навченої моделі YOLOv8n.

Реалізовано завантаження зображень, налаштування порога confidence, визначення класів об'єктів, отримання координат рамок, підрахунок знайдених об'єктів та вимірювання часу inference.

Проведено оцінювання роботи моделі на п'яти тестових зображеннях і порівняно результати за трьох порогів упевненості.

Результати показали, що якість розпізнавання залежить від вмісту зображення та вибраного порога confidence. Модель може правильно визначати об'єкти, але іноді плутає схожі класи або повертає додаткові виявлення.

**Мету практичної роботи досягнуто: реалізовано інтеграцію готової моделі штучного інтелекту у вебзастосунок та проведено аналіз результатів її роботи.**
